# Mapping conventions

`mapping/` is the source of truth for everything Kyubu knows about the supported game builds. Symbol maps, headers, Lua types, reference docs and the Ghidra apply script are generated from it by `kmap export`. `kmap check` enforces the rules on this page; where a rule and this page disagree, the check is right, so report it.

## Layout

| Path | Holds |
|---|---|
| `workspace.toml` | Ghidra pin, analysis options, supported builds and their hashes, cuwo pin, subsystem list |
| `types/<area>.toml` | `[[type]]` (with `[[type.field]]`) and `[[enum]]` (with `[[enum.value]]`), shared by both builds |
| `<build>/functions/<subsystem>.toml` | `[[function]]` entries of one build |
| `<build>/globals.toml` | `[[global]]` entries |
| `<build>/classes.toml` | `[[class]]` entries: RTTI name, vtables and their slots, constructors, destructors |
| `probes/<id>.toml` | recorded probe results (evidence `probe:<id>`; the format and the probe tools are in [docs/probes.md](../docs/probes.md)) |
| `atlas/<subsystem>.md` | how each subsystem works |
| `survey-summary.md` | coverage counts, generated by `kmap report` |
| `exported-names.lock` | every name shipped in a release (see *Name stability*) |

Addresses are virtual addresses at the preferred image base `0x400000`, like the symbol maps.

## Entries

```toml
[[function]]
name = "cube::GameController::update"
address = 0x489130
convention = "thiscall"            # cdecl | stdcall | thiscall | fastcall | usercall
prototype = "void __thiscall cube::GameController::update(cube::GameController* this, int32_t dt_ms)"
subsystem = "core"                 # one of the subsystems in workspace.toml
status = "verified"                # verified | candidate | guess
evidence = ["vtable:cube::GameController:10", "xref:Game::frame"]
source = "kyubu"                   # kyubu | rtti | survey | cuwo | contributor:<handle>
aliases = ["GameController::update"]
notes = "called once per frame with the elapsed milliseconds"
```

- `kind = "site"` marks an instruction inside a function (a mid-hook site), not a function start. `sig_len` sets the minimum signature length exported for it (default 20).
- `[[global]]` has `name`, `address`, `type`, `subsystem`, `status`, `evidence`, `source`.
- `[[class]]` has `name` (the RTTI name), `rtti` (the mangled type-descriptor name), and optionally `type_descriptor`, `bases`, `size`, `constructors`, `destructors`, and one `[[class.vtable]]` per vtable with `address`, `offset` (the sub-object offset, 0 for the primary vtable) and `slots` (function addresses in slot order).
- `[[type]]` has `name`, `kind` (`struct`, `class` or `union`), `size` (0 means "not asserted") and optionally `base` (a single base class, which then occupies offset 0). Each `[[type.field]]` has `offset`, `name`, `type`, `status`, `evidence` and `source`.
- `[[enum]]` has `name` and `size` (in bytes); each `[[enum.value]]` has `name` and `value` and inherits the enum's status unless it has its own.
- `builds = ["cube-0x51D2CE9C"]` limits a type, field or enum to some builds when they differ.
- `retired = true` on a `[[build]]` of `workspace.toml` keeps a build as a record (its entries, probes and symbol map stay and are
  checked) while the loader no longer runs on it: the headers, the Lua types and the game-API checklist describe the other builds.

Field types are primitives (`int8_t` ... `uint64_t`, `float`, `double`, `bool`, `char`, `wchar_t`), pointers (`T*`, any `T`), arrays (`T[N]`) or types defined in `types/`.

## Names

| What | Rule | Example |
|---|---|---|
| Classes | the RTTI name, verbatim, with its namespace | `cube::Creature`, `plasma::Widget` |
| Types without RTTI | the namespace of the code that uses them, PascalCase; cuwo's name when cuwo named it | `cube::CreatureData` (alias `EntityData`) |
| Methods | `Namespace::Class::method`, lowerCamel; constructors `Class::Class`, destructors `Class::~Class` | `cube::GameController::update` |
| Free functions | snake_case, namespaced when the namespace is known | `asset_decode`, `cube::read_packet` |
| Functions whose class is unknown | named as free functions until the class is found, then renamed with the old name kept as an alias | `model_resolver_b` |
| Library functions | the library's own names; exempt from the case rules | `sqlite3_close` |
| Fields | snake_case, cuwo's name where cuwo has one; unknown ranges `_unk_<offset in lower-case hex>` | `hp`, `current_mode`, `_unk_16c` |
| Globals | snake_case, namespaced when the namespace is known | `cube::asset_key_table` |
| Enums | PascalCase type, UPPER_SNAKE_CASE values | `cube::AbilityId::TELEPORT` |

- **Never commit Ghidra's default names** (`FUN_004a1230`, `DAT_`, `LAB_`, `PTR_`, `thunk_FUN_` ...). Unknown code keeps them inside the private project and stays out of `mapping/`.
- **Existing names become aliases, forever.** Mods pass names to `resolve_symbol`; `GameController::update` keeps working after the entry was renamed to `cube::GameController::update`. Aliases are exempt from the case rules.
- `WinMain` and the other conventional entry-point names are allowed as they are.

## Status and evidence

| Status | Meaning | Exported |
|---|---|---|
| `verified` | we stand behind it | yes; loader features may use it |
| `candidate` | probably right | yes, marked as candidate |
| `guess` | a reading aid | never: only applied to Ghidra projects |

Evidence is a list of tagged strings:

| Tag | Strength | Meaning |
|---|---|---|
| `rtti:<class>` | strong | RTTI names the class of this vtable |
| `vtable:<class>:<slot>` | strong | the function is slot N of a named vtable (checked against `classes.toml`) |
| `import:<dll>!<fn>` | strong | thunk or wrapper around a named import |
| `library:<lib>` | strong | identified library function (`sqlite3`, `stl`, `ogg`, `crt`) |
| `probe:<id>` | strong | confirmed in the running game by `probes/<id>.toml`, recorded on the same build |
| `string:"<text>"` | weak | references a telling string (quoted) |
| `xref:<symbol>` | weak | reached from, or reaches, a mapped symbol in a telling way |
| `correlated:<build>:<symbol>` | weak | matched to a mapped function in the other build |
| `cuwo:<path>` | weak | named in cuwo; the path is a file in the cuwo repository |
| `manual:<reason>` | weak | a person's argument in a few words |

**`verified` needs one strong item, or two weak items with different tags.** Lowering a status never needs evidence. `kmap pull` never raises a status.

## Provenance and what may be committed

- Every entry has a `source`: `kyubu`, `rtti`, `survey`, `cuwo` or `contributor:<handle>`.
- Anything that cites cuwo names a file of the cuwo repository (`cuwo:cuwo/entity.pyx`). Only facts are taken from cuwo (names, types, sizes, values), never its code: cuwo is GPL-3.0.
- Evidence strings are at most 80 characters and `notes` at most 300. Describe behaviour in your own words.
- **No game code and no decompiler output** in `mapping/`, ever. Game bytes appear only as generated signatures (at most 64 bytes). Decompiler dumps live in `$KMAP_HOME/decomp/` and are rejected by the public-file check.

## Name stability

A name that shipped in a release is listed in `exported-names.lock`, with the release that first shipped it. It must keep resolving, because mods pass it to `resolve_symbol` or compile against it. `kmap check` fails when a locked name is no longer the name or an alias of an exported entry, including an entry that was lowered to `guess`, and it names the locked name.

- **Renaming.** Keep the old name in `aliases`: `aliases = ["cube::Creature::update"]` on a function, type or enum, and `aliases = ["hp"]` on a field or enum value (the member name only). `kmap export` then keeps the old name everywhere, marked deprecated:

  | Renamed | Symbol maps | Headers | Lua |
  |---|---|---|---|
  | function | an extra entry at the same address, `notes = "deprecated alias of ..."` | a `CW_SYM_` macro with the old name, and a deprecated typedef of the function pointer | `cubeworld.functions` and the FFI typedef under the old name |
  | type or enum | | a deprecated typedef | an FFI typedef, `cubeworld.aliases` (so `cubeworld.cast` takes the old name), and an alias in the stubs |
  | field | | a member of the same type, sharing the field's bytes in an unnamed union | the same union in the FFI module, `aliases` in `cubeworld.types`, and a field in the stubs |
  | enum value | | a deprecated enumerator with the same value | the old key in `cubeworld.enums` |

  Names and aliases of the fields of one type, and of the values of one enum, are unique.
- **What is locked.** Function and global names per build (`[symbols.<build>]`), types and enums (`[types]`), fields as `Type.field` (`[fields]`) and enum values as `Enum::VALUE` (`[values]`), each with its aliases. The 1.0.1 release shipped only the symbol maps, so the lock starts with its 38 names.
- **On release.** `kmap lock` lists the exported names that aren't locked yet. `kmap lock --release` adds them, as shipped in the project version from `CMakeLists.txt` (or `kmap lock --release 1.2.0`); commit the lock with the release. `scripts/package.py --release` refuses to package a release whose names aren't all locked for its version.
- **Removal.** A locked name can be removed only with a major API version: `kmap lock --release` drops locked names that no longer resolve only when `KYUBU_API_VERSION_MAJOR` (`sdk/include/kyubu_api.h`) is higher than when the lock was last updated. Otherwise it refuses and names them.

## Atlas pages

`atlas/<subsystem>.md` explains one subsystem in terms of the mapped entries. Start a page from [atlas/_template.md](atlas/_template.md). `kmap check` enforces:

- **One page per subsystem** in `workspace.toml` (not `library`), plus `primitives.md`, the hand-off inventory. No other pages.
- **Eight sections**, as `## ` headings in this order: Purpose, Key classes, Entry points, Data flow, Client and server, Hook points of interest, Open questions, Depth. Extra `## ` sections are fine (the combat page's design note, for example).
- **Depth.** The section's first line is `not started`, `reconnaissance, reviewed YYYY-MM-DD` or `deep dive, reviewed YYYY-MM-DD`. Reconnaissance means that the key classes and entry points are at least `candidate`, the data flow is sketched, and the open questions are listed. A deep dive ends when the page's exit questions (the game-atlas spec) are answered by `verified` entries.
- **References.** A qualified name in a code span, outside fenced code blocks, is a reference: `cube::Creature`, `cube::Creature::update()`, `cube::CreatureData.hp`, `cube::AbilityId::TELEPORT`. It must be the name or alias of a `mapping/` entry, at any status. The check names the page, the line and the name. Write a name that isn't mapped yet as plain text, and say where it comes from. Unqualified names (`WinMain`, `asset_decode`) are not detected, so link them to their page in `docs/game/`.
